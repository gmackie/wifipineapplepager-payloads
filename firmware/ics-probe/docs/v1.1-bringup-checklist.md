# ICS Probe v1.1 — Hardware Bring-Up Checklist

Follow this checklist once all v1.1 parts arrive. Assumes v1.0 base board is
already working (modbus/serial/can/adc/ble all passing `probe.selftest`).

**Firmware:** Flash the latest master (`8c86e1b` or later — FIRMWARE_VERSION "1.1.0").

```bash
cd firmware/ics-probe
idf.py flash monitor
```

---

## Phase 6: W5500 Ethernet

### Wiring
- [ ] W5500 module VCC → ESP32 3.3V rail
- [ ] W5500 module GND → ESP32 GND
- [ ] W5500 MOSI → GPIO35 (shared SPI bus)
- [ ] W5500 MISO → GPIO37 (shared SPI bus)
- [ ] W5500 SCK → GPIO36 (shared SPI bus)
- [ ] W5500 CS → GPIO4
- [ ] W5500 INT → GPIO5
- [ ] W5500 RST → GPIO6

### Pre-power checks
- [ ] Verify 3.3V at W5500 VCC pin with multimeter
- [ ] Verify CS line idles HIGH (pull-up on module)
- [ ] Plug Ethernet cable into RJ45 jack → link LED should light up when cable connects to a switch

### Firmware verification
```
{"cmd":"probe.info"}
```
- [ ] Response shows `"net": true` in hardware object
- [ ] `"net"` appears in capabilities array

```
{"cmd":"net.dhcp","params":{"timeout_s":10}}
```
- [ ] Returns `{"status":"ok","ip":"..."}` with a valid IP from your DHCP server

```
{"cmd":"net.status"}
```
- [ ] Shows `"link": true`, correct IP, netmask, gateway

### Regression check
- [ ] Existing v1.0 modules still pass: `{"cmd":"probe.selftest"}` — modbus, serial, can, adc, ble all OK
- [ ] CAN handler still works (shares SPI bus with W5500)

## Phase 7: 24V Field Domain Power Supply

### Wiring
- [ ] Phoenix terminal block mounted on breadboard edge
- [ ] Series path: Phoenix(+) → polyfuse → SS54 cathode → junction → 24V rail
- [ ] SMBJ33A: cathode to 24V rail, anode to GND
- [ ] SS54: cathode toward load (band toward 24V rail side)
- [ ] 10µF bulk cap across 24V/GND rail
- [ ] 100nF decoupling across 24V/GND near where chips will go
- [ ] AMS1117-3.3 input from 24V rail, output to field-side 3.3V rail, GND to field GND
- [ ] 10µF cap on AMS1117 output

### Pre-power checks (NO ICs connected yet)
- [ ] Double-check polarity on Phoenix terminal block
- [ ] Apply 24V from bench supply
- [ ] Multimeter: 24V rail reads ~24V ±0.5V
- [ ] Multimeter: field-side 3.3V rail reads 3.3V ±0.1V
- [ ] Polyfuse is not tripped (not warm to touch)
- [ ] Reverse polarity test: briefly swap supply leads → no current flows (SS54 blocks)
- [ ] Remove reverse polarity — restore correct polarity

### Current draw
- [ ] With no ICs, quiescent current should be <5mA (LDO + TVS leakage)
- [ ] Record baseline current for comparison after adding chips

## Phase 8: MAX14906 + AD5420

### ADUM3154 (or Option B isolators) wiring
- [ ] ADUM3154 VDD1 → ESP32-side 3.3V
- [ ] ADUM3154 VDD2 → field-side 3.3V (from AMS1117)
- [ ] ADUM3154 GND1 → ESP32 GND
- [ ] ADUM3154 GND2 → field GND
- [ ] Forward channels (A→B):
  - [ ] A1 = MOSI (GPIO35) → B1 → MAX14906 DIN + AD5420 SDIN
  - [ ] A2 = SCK (GPIO36) → B2 → MAX14906 SCLK + AD5420 SCLK
  - [ ] A3 = MAX14906 CS (GPIO7) → B3 → MAX14906 CS
  - [ ] A4 = AD5420 CS (GPIO10) → B4 → AD5420 LATCH
- [ ] Reverse channels (B→A):
  - [ ] B5 = MAX14906 DOUT → A5 → MISO (GPIO37)
  - [ ] B6 = MAX14906 FAULT → A6 → GPIO9
  - [ ] B7 = AD5420 SDO/FAULT → A7 → GPIO11
  - [ ] B8 = spare (leave unconnected)

### MAX14906 wiring
- [ ] MAX14906 VSUP → 24V field rail
- [ ] MAX14906 DVCC → field-side 3.3V
- [ ] MAX14906 GND → field GND
- [ ] MAX14906 DIN ← ADUM3154 B1
- [ ] MAX14906 SCLK ← ADUM3154 B2
- [ ] MAX14906 CS ← ADUM3154 B3
- [ ] MAX14906 DOUT → ADUM3154 B5
- [ ] MAX14906 FAULT → ADUM3154 B6
- [ ] 100nF decoupling on VSUP and DVCC
- [ ] 4-pin header on DOI0-DOI3 (channel I/O pins)

### AD5420 wiring
- [ ] AD5420 AVDD → 24V field rail
- [ ] AD5420 DVCC → field-side 3.3V
- [ ] AD5420 GND → field GND
- [ ] AD5420 SDIN ← ADUM3154 B1 (shared MOSI)
- [ ] AD5420 SCLK ← ADUM3154 B2 (shared SCK)
- [ ] AD5420 LATCH ← ADUM3154 B4
- [ ] AD5420 SDO → ADUM3154 B7
- [ ] IOUT pin → 2-pin screw terminal (positive terminal)
- [ ] AGND → 2-pin screw terminal (negative terminal / loop return)
- [ ] 100nF decoupling on AVDD and DVCC

### Pre-power checks (ICs installed but 24V OFF)
- [ ] Verify no shorts between 24V rail and GND
- [ ] Verify no shorts between field-side 3.3V and GND
- [ ] Verify CS lines idle HIGH with just ESP32 powered (USB only)

### Power-on sequence
1. [ ] Apply 24V to field domain first
2. [ ] Verify 3.3V field-side rail is stable
3. [ ] Then plug in ESP32 USB (already powered from prior phases)
4. [ ] Watch serial monitor for init messages

### Firmware verification — MAX14906
```
{"cmd":"probe.info"}
```
- [ ] `"dio": true` in hardware object

```
{"cmd":"dio.read"}
```
- [ ] Returns channel states (all should read a stable value)

```
{"cmd":"dio.configure","params":{"ch":0,"mode":"output"}}
{"cmd":"dio.write","params":{"ch":0,"value":1,"confirm":true}}
```
- [ ] Multimeter on DOI0 reads ~24V
- [ ] `{"cmd":"dio.write","params":{"ch":0,"value":0,"confirm":true}}`
- [ ] Multimeter on DOI0 reads ~0V

```
{"cmd":"dio.fault_status"}
```
- [ ] No faults reported

### Firmware verification — AD5420
```
{"cmd":"probe.info"}
```
- [ ] `"iout": true` in hardware object

Connect multimeter in mA mode across the loop output screw terminal (with a 250Ω load resistor in series if your meter needs it):

```
{"cmd":"iout.set_ma","params":{"ma":4.0,"confirm":true}}
```
- [ ] Meter reads ~4.0 mA ±0.1

```
{"cmd":"iout.set_ma","params":{"ma":12.0,"confirm":true}}
```
- [ ] Meter reads ~12.0 mA ±0.1

```
{"cmd":"iout.set_ma","params":{"ma":20.0,"confirm":true}}
```
- [ ] Meter reads ~20.0 mA ±0.2

```
{"cmd":"iout.ramp","params":{"from_ma":4,"to_ma":20,"duration_s":5,"confirm":true}}
```
- [ ] Meter sweeps smoothly from 4 to 20 mA over ~5 seconds

```
{"cmd":"iout.off"}
```
- [ ] Meter drops to ~4 mA (minimum source, not zero)

### Full selftest
```
{"cmd":"probe.selftest"}
```
- [ ] All 8 modules pass: modbus, serial, can, adc, ble, net, dio, iout

### SPI bus conflict check
- [ ] With all 4 SPI devices active, run commands in rapid sequence:
```
{"cmd":"can.scan_ids","params":{"baud":500000,"duration_s":3}}
{"cmd":"net.status"}
{"cmd":"dio.read"}
{"cmd":"iout.status"}
```
- [ ] All four return valid responses (no SPI bus contention crashes)

## Known Issues to Watch For

1. **MAX14906 SPI frame format** — the register layout was implemented from plan
   specs, not the actual datasheet. If `dio.read` returns all zeros or garbage,
   the SPI address/data byte ordering may be wrong. Check the MAX14906 datasheet
   table of registers and compare against `firmware/ics-probe/main/max14906.c`.

2. **AD5420 init — no readback verification.** `iout_is_ready()` may return true
   even if the chip isn't responding. If `iout.set_ma` produces no current, check
   SPI mode (should be mode 1) and the control register value (0x0005 → 4-20mA range).

3. **ADUM3154 power sequencing.** If the field side powers up before the logic side
   (normal in our sequence), the isolator may drive garbage on SPI during the
   window before ESP32 boots. The MAX14906 and AD5420 should tolerate this (CS is
   pulled high), but if you see random faults at boot, add a brief delay in
   `dio_init` and `iout_init`.

4. **Polyfuse trips on inrush.** The MAX14906 + AD5420 + LDO draw ~50mA quiescent,
   well under the 1.5A rating. But if the bench supply has a current spike on
   connect, the polyfuse may trip. Reset by removing 24V for 30 seconds.
